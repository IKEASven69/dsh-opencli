# DESIGN · 无限画布工作台(用户侧复盘画布)

> 状态:设计稿,未实现(按立项约定本轮只设计不写码)。
> 主题:延续 v0.4.4 的「看得见」——v0.4.2/0.4.3 已把「看得见」做进数据层(轨迹落盘、步骤截图、证据包、带出处报告、快照时间线,见 `CHANGELOG.md:26-32`),本设计把它升级成交互层:**数据不再是列表里的行,而是空间里的现场**。
> 姊妹稿:`DESIGN-canvas-vom.md`(agent 侧 canvas 视觉操作可行性,并行撰写中)。本稿与其分工见 §1。

## 0. 一句话主张

**把 agent 每次运行留下的六类数据资产(截图/轨迹/证据/快照/canary/基准),钉在一张可无限平移缩放的画布上,让用户像看案发现场照片墙一样复盘「它到底做了什么」。**

用户价值先行:今天的复盘是三张互相割裂的卡——「运行轨迹」是文本行列表、「时间线」是单个任务的柱状图、证据包在目录里根本看不见面板入口。用户回答不了这些自然问题:

- 「昨天下午那批浏览器操作,页面长什么样?」——要去 `~/.dsh/opencli-shots` 翻目录;
- 「这次失败前面三步发生了什么?」——轨迹行要逐条点开,截图缩略图 48px 基本靠猜(`src/client.ts:1272-1296`);
- 「它昨天动过我的账号吗?」——证据包写在磁盘上,面板无入口(`src/index.ts:2216` 的 evidence-list RPC 存在但没有任何面板消费者)。

画布把这三个问题变成同一个动作:**平移到那一天,看到现场**。

## 1. 两种解读的取舍

「无限画布」在用户提议语境下有两种解读,必须先裁开:

### 解读 A:agent 侧 canvas 视觉操作

指 agent 能操作 canvas 页面(游戏/图表/验证码)——坐标点击、区域识别。这是**执行能力**,归姊妹稿 `DESIGN-canvas-vom.md` 研究(上游 opencli 坐标参数、CDP Input 事件、VOM 系列竞品能力栈)。与本稿的关系:

- **不重叠声明**:本稿不含任何 agent 操作能力设计;A 稿不含任何面板交互设计;
- **互补而非竞争**:A 落地后 agent 在 canvas 页面上的每次点击都会经 `captureStepShot`(`src/index.ts:2533-2554`,SHOT_TRIGGER_SUBS 含 click/drag 等 10 个子命令,`src/index.ts:56`)产生更多步骤截图——**A 的产出恰好是 B 的原料**。A 失败也不断 B 的路:B 的数据源早已在落。

### 解读 B:用户侧无限画布工作台

指用户得到一张可无限平移缩放的画布,任务运行呈现为卡片,截图/步骤/证据钉在其上,带时间轴回放。这是**复盘体验**,本稿的主体。

### 取舍结论:**B 进 MVP,A 归姊妹稿**

| 判据 | A(agent 侧) | B(用户侧) |
|---|---|---|
| 依赖 | 上游 opencli 二进制能力(不可控) | 自有数据资产 + 自有面板(全可控) |
| 数据基础 | 从零论证(见姊妹稿) | 六类资产已落盘,四个 RPC 已在线(trace-list/trace-shot/schedule-history/evidence-list) |
| 受益者 | agent 成功率(间接) | 用户(直接,「看得见」主题本义) |
| 竞品态势 | BrowserSkill 0.3.2 已发「Canvas 视觉 ref」(`docs/PM-RESEARCH-20261003.md:9`),我们在跟 | **市场空白**,无任何插件做用户侧运行画布(§5) |
| 本轮约定 | 姊妹稿只出可行性分档 | 本稿出完整交互与数据模型 |

## 2. MVP 交互稿(文字线框)

### 2.1 与现有四 tab 的关系:**新增第五 tab,不替换时间线**

现有结构:四 tab = 总览/命令/自动化/安全与设置(`src/client.ts:483,1199-1202`);「时间线」是自动化 tab 任务行内的展开 widget(`src/client.ts:1305-1359`),「运行轨迹」卡也在自动化 tab(`src/client.ts:1032-1033`)。

**裁定:新增第五 tab「画布」,时间线与轨迹卡原位保留。** 理由:

1. **时刻不同**:自动化 tab 是「操作时刻」的面(立即跑/开关/删除,运维上下文),画布是「复盘时刻」的面(任务跑完之后看现场)。混在一个 tab 里,操作按钮和复盘手势(拖拽平移)会互相打架;
2. **粒度不同**:时间线是单任务快捷视图,画布是跨任务、跨资产的全局视图。替换时间线等于砍掉单任务运维入口,违背「加路不拆路」;
3. **回归成本**:四 tab 结构自 0.4.0 稳定至今,0.4.3 刚修完一轮 GUI 走查(`CHANGELOG.md:6-12`),大改布局要重走全套走查;
4. **布局无压力**:`.o4-tabs` 是 flex 均分布局(`src/client.ts:313-316`),五个短标签(画布/Canvas)无溢出风险。

跨页跳转做单向轻链接:轨迹卡与时间线各加一个「在画布中查看」按钮(纯 `setTab('canvas')`,与现有 `fillInput` 跳 tab 同款,`src/client.ts:627`),把割裂的三个入口缝起来。

### 2.3 手势与操作

| 操作 | 手势 | 实现要点 |
|---|---|---|
| 平移 | 空白处按住拖拽 | pointerdown/move 改 `translate3d`,不依赖 wheel,规避宿主滚动容器抢事件(§4.2) |
| 缩放 | Ctrl+滚轮 / 触控板捏合 / 工具条 ± 按钮 | 25%–400%,以指针为锚点;**按钮是兜底**——若宿主把 wheel 监听做成 passive 导致 preventDefault 失效,ctrl+wheel 退化为仅按钮缩放,功能不残废 |
| 聚焦 | 双击卡片 | 视口平滑移到该卡并放大到 150% |
| 复位 | 工具条「适应视图」或按 0 | 回到 fit(全部卡片可见) |
| 选中 | 单击卡片 | 底部详情抽屉滑出;ESC 或点空白关闭 |
| 回放 | 回放条 ▶ / 拖动游标 | 按 `at` 升序步进(600ms/步),当前步卡片高亮呼吸 + 懒加载其截图;拖游标时高亮落入时间窗的卡片 |

布局策略(MVP):**时间轴自动蛇形布局**——卡片按时间从左到右排,画布区宽度内放不下即换行;x 位置 = f(at) 当日内线性。确定性布局意味着**零持久化**:不新增任何状态文件,重开面板布局可复现。手动拖放钉住进 P1(需落盘位置文件,见 §3.3)。

### 2.4 卡片内容

**步骤卡**(最小单元,源自 trace 行):

```
┌──────────────────┐
│ ● browser dsh click #login   ← 状态点(绿=exit0/红=失败/琥珀=静默失败措辞)+ 命令
│ [截图 160px 宽]               ← step-*.png;无 shot 字段则整行压缩为纯文本卡
│ 14:32:07 · 840ms · exit 0    ← 本地时区(与 traceClock 同款换算,src/client.ts:1363)
└──────────────────┘
```

**任务卡**(聚合单元,源自定时任务):

```
┌──────────────────┐
│ ◉ site weibo hot            ← 任务名 + 启用态
│ ▂▄▂▂▄▅▅(迷你趋势柱)        ← 快照 bytes 趋势(TimelinePanel 同源数据)
│ ✓ 12/15 · 最近 10-21 08:00  ← verdict 着色规则同任务行(src/client.ts:1016-1019)
└──────────────────┘
```

证据卡 / 报告卡形态见 §3.2 与 §6(P1/P2)。

### 2.5 空态(现实优先)

本机实测:截图目录当前 **0 个文件**(目录结构 `<yyyymmdd>/<session>/` 已建但无 PNG,`find ~/.dsh/opencli-shots -type f | wc -l` → 0)——因为最近跑的都是 site 命令(不经 browser_* 路径)且无失败。**空态是常态而非异常**,设计必须让「只有轨迹没有截图」的画布依然成立:纯文本步骤卡是第一等公民,截图是增强不是前提。完全空态(当日无轨迹)显示引导:「跑一条 browser 命令(如 browser open)后,这里会长出现场」——与现有 tlEmpty/traceEmpty 文案风格一致(`src/client.ts:58,67`)。

### 3.2 映射表(画布概念 ← 来源字段 ← 读取路径)

| 画布概念 | 来源 | 字段映射 | 读取路径(现有 RPC) |
|---|---|---|---|
| **StepCard** | trace 行 | id=`hash(at+cmd)`;t=`at`;status=exitCode(0/非0/静默失败措辞探测,规则同任务行 `src/client.ts:1001`);title=`cmd`;body=`outHead`;thumb=`shot`(可选绝对路径) | `trace-list`(limit 50,跨日聚合,`src/index.ts:1446-1447`) |
| **缩略图位** | shots PNG | `shot` 路径 → base64(宿主侧目录白名单 + 8MB 上限,`src/index.ts:1490-1503`) | `trace-shot`(`src/index.ts:1485`) |
| **TaskCard** | schedules + history | id=`s.id`;name=`s.site`;trend=快照 bytes 序列;verdict=history ok 计数 | `schedule-list` + `schedule-history`(`src/client.ts:1325` 消费先例) |
| **EvidenceCard**(P1) | 证据包 | t=`at`;tint=approval(reason='blocked' 蓝 / 正常执行中性 / 失败红);pair=beforeShot/afterShot;disclaimer=`shotNote`(近似取证声明,**必须随卡展示**,`src/evidence.ts:35-37,64-66`) | 元数据 `evidence-list`(`src/index.ts:2216-2217`);**全文读取需新增 evidence-get RPC(唯一新 RPC)** |
| **ReportCard**(P2) | canary/bench md | t=文件名时间戳;摘要=漂移段/汇总表首行 | 无 RPC,需新增(或复用文件读取约定) |
| 时间轴刻度 | 各卡 `at` | UTC ISO → 本地 HH:MM:SS | 纯前端(`traceClock` 同款) |

关键设计约束:**卡片是派生视图,不是新的持久化实体**。MVP 的画布文档 = `{date, filter, viewport:{panX,panY,zoom}}` 全部活在 React state,刷新即重建——数据真相永远在 jsonl/png/json 里,画布坏了重开就好。这与「报告导出是纯渲染层、零模型介入」(CHANGELOG 0.4.2,`CHANGELOG.md:28`)是同一条架构纪律。

### 3.3 坐标与布局模型

- MVP:确定性自动布局,`x = k · 索引`,行宽 = 画布容器宽(ResizeObserver),换行即蛇形;zoom 只缩放视觉尺寸不改排布;
- P1(手动钉住):新增 `~/.dsh/opencli-canvas-layout.json`(与 statePath/traceDir 同款 `DSH_OPENCLI_*_DIR` 覆盖约定,`src/index.ts:174-186` 先例),存 `{cardId: {x,y,pinned}}`;**未钉住的卡仍自动布局**,钉住是例外不是常态——避免「布局文件损坏=画布不可用」,坏文件直接忽略重排。

## 4. 成本与风险

### 4.1 性能:base64 体积是第一风险

已知的硬数字:

- 单张截图经 `trace-shot` 走 RPC 通道,上限 8MB 文件 → base64 膨胀 4/3 ≈ **10.7MB/张**(`src/index.ts:1500-1503` 上限注释;`src/client.ts:1259` 同款估算);
- 现有缩略图缓存是模块级 Map,封顶 40 条、近似 LRU(`src/client.ts:1247-1264`)——极端情况缓存持有 ~400MB base64 字符串的**理论上限**;实际浏览器视口 PNG 多在数百 KB 量级,40 条 ≈ 数十 MB,可接受但必须守住上限;
- MVP 卡片总量 = trace-list 的 50 行上限(`src/index.ts:1446`),不是无限。

**缓解设计(MVP 内建,不加依赖)**:

1. **懒加载只喂视口**:仅与视口相交的卡发起 trace-shot 请求(IntersectionObserver),50 卡 × 平均 10 可见 ≈ 每次平移 10 张全尺寸图 ≈ 数 MB 级传输,且命中 40 条缓存后零重复 RPC;
2. **缩略层级复用现有 ShotThumb 语义**(48px 缩略 → 点击放大,`src/client.ts:1272-1296`),画布卡片图 160px 仍用同一 base64,靠 CSS 缩放呈现——不为 160px 再要一份图;
3. **P1 才考虑降采样**:宿主侧缩图需要图像库(sharp 等)——**新增 npm 依赖 = 供应链攻击面放大**(PM 调研明示 market #165 事故教训,`docs/PM-RESEARCH-20261003.md:23`),且 package.json files 只发两个 js(`package.json` files 字段),MVP 明确不做;替代路径是客户端 canvas.drawImage 降采样再释放原串(P1 评估)。

### 4.2 dsh 面板容器能力

- **容器是 settings.section 槽位**(`src/client.ts:1231-1233`),不是自由窗口:高度由宿主决定、外层可能有宿主自己的滚动容器。风险:wheel 事件被外层抢走 / passive listener 导致 preventDefault 无效。缓解:平移用 pointer 拖拽(不依赖 wheel);缩放提供按钮兜底(§2.3)。**必须在真机 dsh 面板走查**(本仓已有真机走查纪律,`docs/FIX-20261008-GUI走查修复.md` 即其产物),沙箱里看不出来;
- **零新依赖**:React 18 createElement 手写 transform 画布,估 400–500 LOC(画布容器 + 卡片 + 回放条 + i18n 双语)。与全仓「无 UI 库、双语 STR 表、零 emoji 文字标记」风格一致(`src/client.ts:34,108,1407`);
- **宿主 RPC 契约**:空 args 传 undefined 的坑已有可选链兜底先例(`src/index.ts:1487-1489`),画布新请求全部沿用 `rpc(name, {request})` 包裹形态。

### 4.3 风险清单

| 风险 | 等级 | 缓解 |
|---|---|---|
| 大截图炸 RPC/内存 | 高 | 懒加载 + 40 条缓存封顶 + 8MB 宿主上限(已有);P1 客户端降采样 |
| 宿主容器手势冲突 | 中 | 拖拽平移不依赖 wheel;按钮缩放兜底;真机走查门禁 |
| 数据空态冷启动 | 中 | 纯文本步骤卡第一等公民;空态引导文案(§2.5) |
| 证据卡误导(截图是近似现场) | 中 | shotNote 免责声明强制随卡渲染(`src/evidence.ts:35-37`) |
| 五 tab 视觉拥挤 | 低 | flex 均分 + 短标签;0.2 视觉规范沿用 |

## 5. 竞品差异化声明

**市场上没有这个形态。** 依据:

- T0 霸主 Tencent/BrowserSkill 0.3.2 三件套是「任务历史/审计、**Canvas 视觉 ref**、远程网关」(`docs/PM-RESEARCH-20261003.md:9`)——它的 "Canvas" 是 **agent 侧**视觉引用(给模型看的),不是用户侧运行画布;其 issue 流长期暴露「借用模型/更新可靠性/Windows」三大老伤(`docs/PM-RESEARCH-20261003.md:61`),没有可复用的落盘资产层;
- 官方注册表 4412 条实测盘点(PM 调研全量)中 UI 面板类插件 1855 个,头部全是「浏览器控制面板」形态,**无空间画布复盘形态**;
- 官方 Browser Use 结构性做不了:「无持久身份与存储」(`docs/OPENCLI-ROADMAP-20260922.md` 主线 B 注),而画布的全部原料恰恰是我们的持久化资产。

**差异化一句话**:别人给模型看 canvas,我们给**用户**看运行现场——每张卡片自带出处三元组(命令 + 时间 + 文件路径),与报告导出的出处纪律同源(`CHANGELOG.md:28`),零模型介入、零编造空间。

## 6. MVP 裁剪与不做清单

### MVP(P0,一次交付)

1. 第五 tab「画布」(双语,含空态);
2. 卡片类型:**步骤卡 + 任务卡**(四种里裁掉证据卡/报告卡);
3. 时间轴自动蛇形布局(当日视图,trace 50 行上限),**无手动摆放、无布局落盘**;
4. 平移/缩放/聚焦/适应视图(拖拽 + ctrl+wheel + 按钮兜底);
5. 时间轴回放条(步进高亮 + 截图懒加载);
