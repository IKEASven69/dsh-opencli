### 正文

最近社区的两篇插件盘点(《15 款实用插件》《16 个超火插件》)都介绍了 dsh-browser 这类浏览器插件:给 agent 一双"通用浏览器操作"的手——打开页面、点击、填表、截图,拿到的是网页本身。这类工具解决的是"agent 能不能操作浏览器"。

但如果你想让 agent 持续用**你自己登录好的账号**办事——每天早上把掘金热榜推到飞书群、盯某个关键词一出现就通知、采集结果能对账——你会发现"能点页面"和"能可靠地办事"之间还差四层。这篇以我们做的开源插件 dsh-opencli 为例,把这四层拆开讲(思路通用,换别的实现也成立)。

#### 第一层:通用原语 → 结构化站点命令

通用浏览器操作的流程是:打开页面 → 等渲染 → 找到元素 → 抽内容,每一步都可能失败,而且每一步都花 token。dsh-opencli 的做法是把这一整段预编译成**结构化命令**:上游 OpenCLI 生态为各站点维护适配器,插件把目录蒸馏后注入 systemPrompt,agent 第一轮就选对命令。

当前上游 manifest 实测:**171 个站点、1225 条命令**(2.0.3;对外口径保守写 170+/1200+)。一条 `site juejin hot` 直接返回结构化结果,不用现场试错。适配器没覆盖的页面,依然可以退回通用网页原语——两条路并存,不是二选一。

#### 第二层:写操作要过审批门

agent 能操作浏览器之后,最怕的不是读,是写:发帖、删评、改设置。dsh-opencli 的审批门是 **fail-closed** 的:权限不明的命令一律按写处理;写命令默认弹审批窗,人点了允许才执行。

这套门有专门的回归:22 行攻击表(17 种写/越权形态逐条弹审批、5 条只读对照验证不误伤)、3 条独立通道(site_batch 批量、benchmark、canary 各自带只读门),再加 200 次可复现模糊测试,不变量只有一条:**凡放行,必是只读意图**。测试仓库公开,可以直接跑。

#### 第三层:exit 0 不等于拿到数据

无人值守采集里最阴的失败是"静默失败":命令退出码是 0,输出也有内容——但内容其实是风控页/登录墙/空壳页。dsh-opencli 加了一层**执行真实性判定**:确定性规则(失败词汇表、错误 JSON、空输出)+ 亚秒决策模型兜底,两层判定把这类结果标成"疑似静默失败",定时任务按失败重试。每份快照可回溯到产生它的命令与时间——数据带出处,可对账,不是模型转述。

#### 第四层:一次性调用 → 定时采集与推送

上面三层都成立之后,"让 agent 每天早上 9 点自动干这件事"才可靠:dsh-opencli 支持持久化 cron 任务,失败自动重试(撞登录/风控墙时退避加长到 2 分钟以上,避免加重风控信号),watch 关键词命中或内容增减(新增/消失/位移)时推送——飞书、钉钉、企业微信、Telegram、邮件、通用 webhook 都行,正文附"与上次相比"的差异段。采集轨迹全程落盘,面板里可以逐步回放"agent 这次到底看到了什么"。

#### 装起来什么样

前置是 OpenCLI CLI + BrowserBridge 浏览器扩展(驱动你日常用的 Chrome/Edge,登录态就是浏览器里那个),然后 `npm i -g @cold777/dsh-opencli`,重启 dsh 即可。README 有逐步安装说明;扩展没装时插件会如实告诉你哪些命令还能跑、哪些不能,不假装能跑。

边界也说清楚:它跑在**真实登录态**上,天然不适合匿名检索场景(dsh 内置 web 工具管那半);需要一台有真实浏览器的机器;写操作永远等人工点头。

仓库:https://github.com/IKEASven69/dsh-opencli (MIT,面板中英双语)
