# 0.2.0 测试报告 · 性能基线(rpc-bench,2026-11-24 包前实测)

> 脚本:`.build-tools/rpc-bench.cjs`(只读;五项)。0.2.0 性能包(B/E)全部基于本基线设计,包后复测同一脚本对比。取证:`node .build-tools/rpc-bench.cjs`(2026-11-24T03:24Z)。

| # | 项 | 实测 | 对应 0.2.0 改动 |
|---|---|---|---|
| 1 | `--version` spawn | 中位 **83.6ms**(n=5) | — |
| 2 | `daemon status` spawn | 中位 **328ms**(n=5,首拍 510ms 冷) | PF4:三处 entry 路径 15s TTL(预检/重探保持真探) |
| 3 | 事件档整读 | 0.54ms @ 15KB/76 行 | PF7 尾读:满档(5MB)预估 200-500ms→尾读路径(本机档小未触发,满载待打点) |
| 4 | schedule-history 读放大 | JSON.parse 法 0.28ms @ 3 份/6B vs stat 法 0.12ms | PF1:20×50 满载≈1000 次同步解析→statSync(本机数据小,满载推算待实测;小数据 stat 已快 2.3×) |
| 5 | state.json stringify | 29KB / 0.13ms | PF11 仅观测(>512KB 每日提醒) |
| 6 | adapters 单页 spawn | **351ms**;13 页+governor 间距 ≈ **14.3s 冷构建** | PF2:在途去重(双份翻页风险消除)+翻页免 750ms 限流间距 |

## 读法

- #2/#6 为实锤(实测直接支撑 PF4/PF2 收益);#3/#4 本机数据量小,0.2.0 的修复价值在**结构性消除随时间恶化的放大路径**(满载量级为推算,已标注)。
- 满载复测构造:事件档填充至 5MB / 快照目录 20×50 份后重跑本脚本即为实测;列入 0.2.1 可选。
