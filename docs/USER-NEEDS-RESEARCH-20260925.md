## 三、用户需求(按信号强度排序)

1. **适配器新鲜度**(53% 的 issue):站点一改版就断,用户等修复。
   → 对插件的启示:知识层(sitemap/pitfalls/命令语义)+ 浏览器兜底不是"锦上添花",是对冲上游 53% 积压的唯一杠杆;登录态桥让"适配器坏了→同一浏览器自由浏览"无缝降级。
2. **失败要说真话**(22%+19% 交叠):"clicked: true 但什么都没发生"类静默失败毁掉无人值守管线的数据可信度。
   → 对插件的启示:so_verify(noul 独立第二意见)直接命中;audit-list 的透明化方向正确。
3. **后台/无人值守可靠性**:#2520 证明最小化窗口下操作会假成功——**定时任务场景(我们插件的主线 B)正是受害者**。重试 ×3 已做,还需执行前健康检查。
   → site_batch 派发前每站 noul 体检(SYSTEMONE 方案表内已有,提级实现)。
4. **反爬/风控共存**:#2470 umbrella、#2456 429、#2528 误报——用户要的是"别把我的账号搞封"。
   → 面板限流限域已有;pitfalls 知识(每站风控点)进知识包。
5. **可编程性**:doctor --json、标签页生命周期 RFC——power user 要可解析输出。
   → 插件本身就是机器可读层(normalized {exitCode, stdout, stderr}),方向已对。

## 五、调研→升级优先级映射(结论)

| 需求信号 | 对应升级项 | 原排期 | 调整建议 |
|---|---|---|---|
