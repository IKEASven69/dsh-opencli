# 0.4.6 版本规划(呈审 · 2026-10-30)

> 原则:别人有的我们也要有且更好;没人有的我们要有。
> 输入:PM-RESEARCH-20261030(竞品三战线)+ 同名竞品差距调研 + 0.4.5 遗留(npm 作用域名待拍板)。
> 规模判断:A 是架构级大项(引擎+全族迁移),B 是数据产品深化主打,C/D 小而硬。

## A. 直连传输引擎(对标 d342784178 唯一优势,做得更好)——头牌

**它有**:POST /command 直连 daemon,10-20ms/命令(CLI 路径 1400-1800ms,~100×);5 个工具。
**我们更好**:

- A1 **daemon 客户端层**:能力探测(启动时打一次探针,识别 /command 形状,1.x/2.0 嗅探——与 CLI 信封
  双版本同思路)+ **CLI 全量兜底**(直连任何失败静默降级 CLI 路径并记 trace,用户零感知)。对手没有
  兜底,daemon 版本变形即挂;我们在版本战争环境下必须带。
- A2 **覆盖全原语族**:opencli_do/state/screenshot/canvas 三件册/chrome call 全走直连(对手只有 5 个
  独立工具);站点命令(适配器在 CLI 侧)维持 CLI 路径,如实文档化边界。
- A3 **批量求值通用化**:一次往返多条表达式(参数化上限,对手固定 40),opencli_do 一次跑完整流程
  的多步脚本不再逐命令缴往返税。
- A4 **基准背书**:benchmark 巡检加"直连 vs CLI"延迟对比列,发版说明带前后数字。

验收:全原语族真机走直连成功+故意杀 daemon 后自动回退 CLI 全绿;22 套件+单测(含形状嗅探矩阵);
延迟对比数字落 benchmark 报告。

## B. 人机协同与体验大升级(用户核心诉求)——并列头牌

**可行性已核验**:宿主 llm 服务以名 \"llm\" 注册于根 ctx(dsh-llm super(ctx,'llm'),面板会话同源),插件
static inject:['llm'] 即可调用——NL 映射引擎就位;面板样式为 392 个 o4-* 类+注入式 CSS 常量,设计
系统底子已在,升级=演进。

### B1 自然语言指挥台(总览 tab 主行动)
- 试试看升级双模式:命令模式(现状)/ **NL 模式**——输入「每天早9点把掘金热榜发到我飞书」→ llm 映射
  成结构化意图{site 命令/cron/watch/通道}→**映射预览卡**(逐字段展示,可改)→确认执行。
- 覆盖三场景:即时查询/定时创建/盯变化设置——五 tab 表单流压成一句话。
- 诚实边界:llm 花用户模型额度,显式按钮触发不自动调;映射预览必过(不许黑箱执行);失败一键回退表单。
- 新增 RPC:nl-intent(入 NL 文本,出结构化意图;llm 注入失败返回引导)。

### B2 SKILL.md 人机协同层(agent 侧自然语言)
- 场景化工作流文档:一句话让 agent 建定时/盯变化/出报告/装插件;工具在则用工具,不在则指路。
- install-opencli-skill 已有,本轮做内容升级(对齐 0.4.6 能力)。

### B3 UI 高级感设计系统与动效
- tokens 统一(色板/字阶/间距/圆角/阴影,暗色基调);五 tab 视觉逐页重构,重点突出(总览只留一个主行动)。
- 动效体系:卡片入场 stagger/hover 浮起/tab 过渡/数字滚动/时间线柱生长/截图点击放大 lightbox/
  加载骨架屏/运行态呼吸灯/通知 toast——全部 transform+opacity(60fps 不触重排),尊重 reduced-motion。
- 验收:逐 tab 截图走查 + gui-verify 断言动效类;「看看 UI 就高潮」不是口号,是走查项。

### 使用场景(设计的锚)
1. 新用户:开面板 3 秒内看到唯一主行动(NL 指挥台),输入第一句话就有数据卡片回报。
2. 想看数据:一句话→真实数据卡片,不懂命令语法。
3. 想盯变化:一句话建成 定时+watch+推送(原需跨两 tab 填三张表单)。
4. agent 用户:SKILL 一句话完成全流程,人机同能力。
5. 复盘:画布回放(已有),视觉与全面板统一。

## C. 快照差异推送(没人有的)——数据产品深化主打

**现状**:watch 是关键词命中;用户定时采集的真实目的是"盯变化",命中推送只回答"出现了",不回答"变了什么"。
**做**:

- B1 相邻快照结构化 diff:列表型 JSON 输出(热榜/搜索结果类)逐条比对,产出新增/消失/变更三列表;
  非列表输出回退"字节变化+规模变化"摘要。
- B2 推送正文升级:`🔔 Watch 命中` 之外新增 `📊 变化` 事件——新增 2 条(标题…)/消失 1 条(…)/
  上升 3 位(…);面板事件流同款。
- B3 报告导出加 diff 段(两期对比);画布卡片流天然承载前后快照对读(卡片已带快照路径)。

验收:真实 juejin/zhihu 热榜连续两跑 diff 正确(人工构造已知变化验证新增/消失/位移三形态);
推送真机送达含变化摘要。

## D. 推送渠道模板化(别人弱有,做得更好)

- C1 webhook 通道升级"平台预设":飞书/钉钉(含加签)/企业微信/Telegram 四预设,面板下拉选平台、
  只填 token/webhook,模板自动拼 URL 与消息卡格式(现通用 webhook 要求用户自己懂各平台格式)。
- C2 通道测试按钮:面板一键发测试消息(现要真跑一次任务才能验证配置)。

验收:四预设真机投递(本地接收器验载荷格式)+测试按钮;单测覆盖加签算法。

## E. 工程加固(小而硬)

- D1 **工具 output schema 真调用一致性测试**:宿主 additionalProperties:false 严格校验,直调
  execute() 不触发、真调用才炸(竞品踩坑实录)——CI 加一层"经宿主校验器跑全部工具样例输出"。
- D2 dsh 0.2.2 跟踪:alpha→stable 后适配一轮(套件随宿主版本记录)。
- D3 npm 作用域名发版(待拍板 @ikeasven69/dsh-opencli):发出去自动进 npm 目录,与同名竞品并排
  区分;package.json 双名准备(发布时改名,仓库安装路径不变)。

## 明确不做(记录理由)

- 远程网关(BrowserSkill 有):与"本机登录态"定位相抵,供应链/凭据风险大,不跟。
- 全页/后台 tab 截图(BrowserSkill 有):上游 CLI 已有 --full-page 我们已透传;后台 tab 截图跟
  上游能力走,不自研。
- canvas 类型化 visual ref(BrowserSkill 有):我们 canvas 层已有 region crop 原语(vom.ts
  buildRegionCropJs),0.4.6 不展开,列 0.4.7 候选——复盘面(位图落盘进画布)已是独占,不追操作面。
